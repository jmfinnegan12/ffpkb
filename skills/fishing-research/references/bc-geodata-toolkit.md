# BC Geodata Toolkit — optional enhancement for British Columbia reports

Scope: **British Columbia regions only** (any BC drainage — Kootenay, Vancouver Island, Fraser, Peace, etc.). These are BC/Canada government systems (BCGW/DataBC schemas, NRCan); they do not apply to Idaho, Washington, or other non-BC reports. Built and verified during an eastern-BC (SE Kootenay → Kakwa) remote scouting report — the first time this was used. Treat as a proven reference, not a mandatory step: reach for it when the angler wants coordinates, access/gravel-road detail, or maps for a BC report; skip it for a conversational or non-spatial one.

**No GIS/fisheries MCP connector exists** (registry search returns empty) — everything here is free, public, no-auth, and pulled via plain `WebFetch` (for JSON/GeoJSON) or a local Python script (for anything that needs to render an image, since WebFetch can't return raw binary).

## What each layer adds, and how to pull it

| Need | Source / endpoint | Notes |
|---|---|---|
| **Fish presence** | WFS `pub:WHSE_FISH.FISS_FISH_OBSRVTN_PNT_SP` @ `openmaps.gov.bc.ca/geo/pub/wfs` | Presence/observation points only, not counts. Each feature has `ACAT_REPORT_URL` pointing to the source survey. |
| **Fish presence — richer** | WFS `pub:WHSE_FISH.FISS_HIST_FISH_DST_LIN_PUB_SVW` | Stream-*segment* reaches per species (line geometry), not just point dots. |
| **Size/abundance inference** | WFS `pub:WHSE_BASEMAPPING.FWA_STREAM_NETWORKS_SP` — fields `STREAM_ORDER`, `STREAM_MAGNITUDE`, (`GRADIENT` usually null) | Captures channel size/capacity — how much water there is — not habitat suitability. **See "Bull trout habitat inference" below before treating this as sufficient on its own**; it systematically overrates warm, low-gradient, lake-influenced reaches for bull trout specifically. Fine as-is for cutthroat/rainbow numbers, where the bias matters much less. Always tag `[inferred-habitat]`. |
| **Stream temperature (the actual thermal-regime layer)** | *Stream Thermalscape Scenarios for BC* (Islam/Moore et al. 2024) — [Dryad, DOI 10.5061/dryad.bzkh189fk](https://datadryad.org/dataset/doi:10.5061/dryad.bzkh189fk), free/no-login/OGL-BC | Models **predicted August mean stream temperature** on the same FWA reaches used for order/magnitude — joins directly. Covers all of BC (Kootenay/Columbia/Fraser/Peace), historical (1981–2000, 2001–2020) + future scenarios. **One-time ~1.9 GB ESRI `.gdb` download, not a live API** — read locally with GDAL's OpenFileGDB driver (geopandas/fiona/`ogr2ogr`), no ArcGIS needed. Excludes reaches <1 km² and lakes, so it nails the mainstem/foraging read but misses the smallest cold natal tributaries. **NorWeST (the obvious US equivalent) does NOT cover BC** — confirmed, it stops at the 49th parallel; don't waste time trying it here. |
| **Barriers/connectivity** | WFS `WHSE_FISH.PSCIS_ASSESSMENT_SVW`, `WHSE_BASEMAPPING.FWA_OBSTRUCTIONS_SP`, `FWA_LAKES_POLY` | Falls/culverts that block migratory fish; lake connectivity for migratory bull trout. **Make this a mandatory check, not an occasional one, for any "migratory/fluvial/adfluvial bull trout" claim** — a downstream barrier invalidates the claim regardless of how good the size numbers look upstream (see the Doré River case study below). |
| **Roads / gravel vs. paved** | WFS `pub:WHSE_BASEMAPPING.DRA_DGTL_ROAD_ATLAS_MPAR_SP`, field `ROAD_SURFACE` (`loose`/`rough`≈gravel, `paved`, `decommissioned`/`overgrown`≈deactivated) | Also `pub:WHSE_FOREST_TENURE.FTEN_ROAD_SECTION_LINES_SVW` for FSR tenure, and Rec Sites & Trails BC layers for rec-site closures. |
| **Freshet / is-it-clear-yet** | ECCC OGC API `api.weather.gc.ca/collections/hydrometric-stations` (find gauges by bbox) and `/hydrometric-daily-mean` (`?STATION_NUMBER=xxxx&datetime=YYYY-MM-DD/YYYY-MM-DD`) | Clean JSON, no auth. Directly answers "is this stream past freshet and low/clear by the trip window?" Realtime variant: `/hydrometric-realtime`. |
| **Snowpack** | BC River Forecast Centre CSVs: `env.gov.bc.ca/wsd/data_searches/snow/asws/data/{SW,SD,TA,PC}.csv` | Wide-format (station-per-column); corroborates freshet timing. |
| **Current wildfire** | WFS `pub:WHSE_LAND_AND_NATURAL_RESOURCE.PROT_CURRENT_FIRE_POLYS_SP` | **Geometry field is `SHAPE`, not `GEOMETRY`** — a `BBOX(GEOMETRY,...)` filter on this layer 400s. Query without a geometry filter and count in-region, or filter client-side. If this fails, fall back to a news/BC-Wildfire-dashboard search — active fires are also time-sensitive enough that a fresh web search often beats a stale geodata pull anyway. |
| **Regs / classified waters / non-resident booking** | No API. BC Freshwater Fishing Regulations Synopsis PDFs, per region (`region_4_kootenay.pdf`, `region_7a_omineca.pdf`, `region_7b_peace.pdf`, etc.) | Fetch/parse the PDF directly. Remember: **classified water ≠ booking water**. Most classified waters are walk-up (pay a per-day supplemental licence, no reservation); as of this writing only Skookumchuck Creek, Michel Creek, and the Wigwam River run an actual non-resident booking/quota system — don't conflate the two when scoping a "no advance booking" request. |
| **Base map imagery** | NRCan hillshade WMS `datacube.services.geo.ca/ows/elevation` (layer `dtm-hillshade`); DataBC ArcGIS `export` endpoints (`delivery.maps.gov.bc.ca/arcgis/rest/services/.../MapServer/export`) | Use `export`, not `query`, on DataBC ArcGIS services — `/query` returned HTTP 400 "operation not supported" in testing. |
| **Survey/abundance/genetics reports** | EcoCat/ACAT report repository (`a100.gov.bc.ca/pub/acat/...`), linked from each FISS observation's `ACAT_REPORT_URL` | **Browser-only** — the API 500s to automated fetch (WebFetch). This is where the real size/abundance numbers and cutthroat hybridization/purity studies live; if you need them, drive the in-app browser to individual report URLs rather than trying to script it. |

## Axis-order gotchas — the single biggest time-sink

Three different, incompatible bbox/coordinate conventions show up across these APIs. Getting one wrong silently returns zero features (not an error) — always sanity-check with a known-good small query first.

- **WFS `CQL_FILTER=BBOX(...)`** (FISS, FWA, DRA, fire): **`minLon,minLat,maxLon,maxLat`** (x,y order).
- **WMS 1.3.0 + `crs=EPSG:4326`** (NRCan hillshade, DataBC WMS overlays): **`minLat,minLon,maxLat,maxLon`** (lat,lon order — the opposite of the WFS convention above).
- **Overpass API** (OSM, if used for road-surface ground-truth): `south,west,north,east` (lat,lon,lat,lon — yet another arrangement).
- **DataBC ArcGIS `export`**: accepts a plain `bbox=minLon,minLat,maxLon,maxLat&bboxSR=4326` — straightforward, but only via `export`, not `/query`.

## Species name strings vary by layer — don't assume

- FISS point layer: `'Bull Trout'`; westslope cutthroat is **not** the literal string `'Westslope Cutthroat Trout'` (returns zero) — it's `'Westslope (Yellowstone) Cutthroat Trout'` or plain `'Cutthroat Trout'`. Use `SPECIES_NAME LIKE '%Cutthroat%'` or filter on `SPECIES_CODE` (`BT`/`WCT`/`GR` for grayling, or `'Chinook Salmon'`/`'Sockeye Salmon'`/`'Kokanee'` for anadromous/forage-linkage checks) instead of guessing the display string.
- Verify the exact string per layer with a cheap `&propertyName=SPECIES_NAME` probe before running the real query — the distribution-line layer has used a different literal string than the point layer.
- **The FISS layer's native geometry is stored in EPSG:3005 (BC Albers), not 4326** — a `BBOX` filter that omits the explicit `,'EPSG:4326'` fifth argument (or otherwise assumes the query bbox's CRS matches the storage CRS) can silently return zero features. Always include the explicit SRS in the CQL BBOX call, as shown in the recipe above.

## Salmon / kokanee — a structural, not per-water, question

Before spending research time checking every candidate individually: **the Columbia/Kootenay basin in Canada is permanently blocked to true anadromous salmon** by Grand Coulee and Chief Joseph dams downstream in the US (no fish ladders — confirmed, applies to every BC water in that basin, no exceptions). Only **kokanee** (landlocked sockeye) occur there, and BC interior kokanee runs spawn **September–October** — irrelevant to a summer (Jun–Aug) trip window as a forage input, though a real reason to suggest a fall return trip if a candidate has a strong kokanee signal. **The Fraser basin (and other undammed BC drainages) can have real Chinook/Sockeye/Coho runs** with upper-Fraser stream-type Chinook typically arriving/staging June–August and spawning August–September — check FISS for `'Chinook Salmon'` etc. per candidate here, since a genuine egg/flesh forage boost to bull trout is plausible and worth flagging when the timing overlaps the trip window (it did, materially, for two waters in the eastern-BC report). Direct recreational harvest of these salmon runs in remote headwater reaches is essentially never legal/available — these are typically conservation-listed stocks.

## Bull trout habitat inference — temperature & connectivity

Stream order + magnitude is a proxy for *channel size / adult foraging capacity*, not habitat suitability — and for **bull trout specifically** it's biased toward overrating warm water. BC's own stream-temperature research (Moore, Nelitz & Parkinson 2013) associates high stream temperature with large, low-relief, lake-influenced watersheds — the same profile the order/magnitude proxy flags as "big-bull potential." Bull trout are the most thermally sensitive salmonid in the region: optimal mean-August temperature 6–8°C, rarely present above 11°C, occurrence collapses above ~14–16°C max daily ([Dunham, Rieman & Chandler 2003](https://www.tandfonline.com/doi/full/10.1577/M02-028)), and BC agency guidance ([Hagen & Decker 2011](https://a100.gov.bc.ca/pub/acat/documents/r36019/Hagen_Decker2011FishTechRptNoFTC110_1365443244574_3caaeb98364a8ded524d724f72cbf3906bdd3433d688f93aff3fc7e9aef095f0.pdf)) puts the presence ceiling near 15°C — rainbow trout displace bull trout above ~13°C, which is likely *why* a cutthroat/bull → rainbow transition shows up heading toward warmer, lower-elevation water, even when nothing in the pipeline explicitly measured temperature. **Small spring-fed or high-elevation streams can be colder — and better bull trout water — than a bigger lower-elevation river, and glacial melt (usually treated purely as a clarity problem) is actually a thermal *asset* for bull trout,** not a habitat negative.

**Fix:** pull the Stream Thermalscape layer (above) for the candidate's FWA reach — historical 2001–2020 August mean ≤~12°C supports a resident/rearing call, 12–15°C is marginal/staging-only, >15°C should veto a "resident/rearing here" claim (adults may still transit warmer water). Treat this and connectivity (barriers/lake access) as **gates** a candidate must clear; apply order/magnitude as a **capacity score** only within water that's already thermally suitable and connected — not as one flat combined guess. Revised confidence tags, most to least evidentiary: `[survey/telemetry]` (real data) > `[presence+thermal+connectivity]` (FISS + Thermalscape + verified connectivity — the new default target) > `[presence+size-proxy]` (today's default, no temperature check) > `[size-proxy only]` (FISS gap, proxy alone — flag as unvalidated).

**Case study for why connectivity matters as much as temperature:** a river can have an impressively high stream order/magnitude and still be capped to a small resident/juvenile fishery if there's an uninvestigated barrier — a waterfall or culvert a few km upstream of where the "big migratory bull trout" claim is being made. Always check `FWA_OBSTRUCTIONS_SP`/`PSCIS_ASSESSMENT_SVW` before making a fluvial/adfluvial claim, not just the size numbers.

Gradient itself is usually better derived from a DEM (elevation drop ÷ reach length, using the same NRCan hillshade/elevation data already in the map pipeline) than trusted from the FWA `GRADIENT` field, which is null for most segments in practice.

What still can't be fixed by more geodata: actual abundance and fish size (FISS stays presence-only), micro-scale spawning-gravel quality, pool frequency and cover, and this year's actual clarity/road conditions — those remain `[guide-forum]`/on-the-ground-verification territory no matter how good the modeled layers get.

## Static maps: what actually works, in order

1. **Base:** NRCan `dtm-hillshade` WMS. It returns pure white for NoData (common in flatter valley floors) — composite it over a solid land-tone background and knock the white pixels transparent first (`numpy`: mask pixels where R,G,B are all >247, set alpha 0), or the valley bottoms — exactly where the rivers are — render as blank white gaps.
2. **Rivers AND roads:** pull both `FWA_STREAM_NETWORKS_SP` (order ≥ 3) and `DRA_DGTL_ROAD_ATLAS_MPAR_SP` as **WFS vectors** and draw them as matplotlib lines — rather than using the WMS raster overlay for either. **The WMS overlay's default styling for roads is essentially invisible against a hillshade — this was shipped once and was the maps' biggest miss** (the FSR access network is the whole point of a "gravel access" report). Style roads by `ROAD_SURFACE`: `loose`/`rough` (gravel/FSR) as a bold dashed color that pops, `paved` as a solid neutral line, `decommissioned`/`overgrown` thin and faint (still shown, de-emphasized); drop `ROAD_CLASS` values `skid`/`trail` (not real vehicle roads). Style streams weighted by `STREAM_ORDER`. **Both vector pulls are fast on a tight per-map bbox (~1–2s) even though the same query can time out on a full ~1° research-pass bbox** — keep map bboxes tighter than the research bbox that fed them.
3. **Overlays:** lakes, parks, and current fires as transparent WMS raster composites on top (these work fine as WMS rasters — it was specifically the road layer's default symbology that was the problem, not WMS overlays in general). **Force every fetched overlay image to the exact same pixel dimensions as the base before compositing** (`PIL.Image.resize`) — WMS servers don't always honor the requested `width`/`height` exactly, and `Image.alpha_composite` throws if sizes mismatch by even one pixel.
4. **Points/labels/scale bar/legend:** plot in matplotlib on top of the composited raster, `ax.set_aspect(1/cos(mid_latitude))` to correct for longitude compression at BC's latitudes.
5. A reusable version of this renderer is at `scripts/build_map.py` in this skill, copied from the working version built for the eastern-BC report. Treat it as a **seed script** — copy it into the working scratchpad, edit the bbox/points/overlays for the new report's geography, run it. Don't try to make it a fully generic parameterized tool before it's been reused a few more times.

## Honest limits — accept these, don't fight them

- Fish **size and abundance are inferred**, not measured — FISS gives presence only. Report every size/abundance claim as `[inferred-habitat]` (from stream order/gradient), `[report]` (an actual survey/telemetry PDF you found), or `[guide-forum]` (anecdote), each with a confidence tag, matching `quality-bar.md`'s taxonomy.
- EcoCat/ACAT survey reports (real numbers, genetics/purity studies) require a manual browser pass — budget for it if the report needs hard numbers, don't assume a research subagent can script its way in.
- Regulations have no API — always trace to the actual regional synopsis PDF, never a guide page's paraphrase (this was already the rule in `quality-bar.md` §4; it doesn't relax just because geodata is involved).
- Road/FSR passability and glacial-turbidity/clarity are weather- and year-dependent — geodata gives you the *type* of road/stream (gravel vs. paved, glacial vs. snowmelt), not this month's actual condition. Still needs a forum/guide "what's changed" pass per `quality-bar.md` §1.
